# Q5.2 performance and endurance

Status: **noninteractive process/endurance evidence partial; screen/input acceptance explicitly deferred**.

Q5.2 owns the acceptance harness and evidence format, not a second runtime or
provider implementation. The production ownership seams remain Rust-owned:
EditorHost owns the selected official VS Code/OpenVSCode WebView lifecycle,
TerminalRuntime owns tmux, and AgentRuntime owns Herdr. A performance regression is fixed in that owning seam;
the harness never changes a budget to make a result pass.

## Reproducible harness

The contract is implemented by [`scripts/q5-performance.py`](../scripts/q5-performance.py)
and checked by [`scripts/check-performance.sh`](../scripts/check-performance.sh).
The checked-in local report is [`evidence/q5.2-local-report.json`](evidence/q5.2-local-report.json).

```sh
python3 scripts/q5-performance.py --plan
scripts/check-performance.sh
```

`--check` validates the exact scenario set, budgets, sample policy, scale
matrix, independent crash matrix, tmux transition cases, and redaction rules.
`--self-test` includes adversarial fixtures for incomplete and over-budget
timings, hidden-surface duration/count/identity/Bridge/dirty failures, every
Quit/relaunch cycle fact, and every required redaction declaration. The
report validator is intentionally usable without a GUI, official VS Code CLI, or
external provider.

The native process driver is [`scripts/q5-native.py`](../scripts/q5-native.py).
It performs a non-identifying host/artifact/GUI probe by default, discovers a
separately installed official VS Code `code` CLI, and writes the
bounded report [`evidence/q5.2-native-report.json`](evidence/q5.2-native-report.json):

```sh
python3 scripts/q5-native.py --probe
python3 scripts/q5-native.py --check --report docs/evidence/q5.2-native-report.json
```

On a Mac with a WindowServer session and official VS Code installed, run the
current process-only attempts explicitly after making the local server-license
decision:

```sh
python3 scripts/q5-native.py --scale-endurance --accept-official-vscode-license
python3 scripts/q5-native.py --execute --accept-official-vscode-license
```

Neither command drives focus, clicks, keyboard input, menus, or screenshots.
`--scale-endurance` is the authoritative current gate. It starts the real app
and providers, proves 8 Workspaces/16 live Agents/9 Editor WebViews, retains at
least 5 hidden Editors for 10 minutes while checking identity/Bridge/dirty
continuity, verifies owned cleanup, and performs five process-targeted
Quit/relaunch cycles. The Quit request uses the exact PID's ordinary Cocoa
termination path; it does not click native UI.

After the hidden hold starts, continuity completion is strictly read-only. It
compares the Rust-owned AppSnapshot, immutable EditorHost surface inventory,
and Bridge observations; it never calls a WebView show/focus/hide path to
produce a passing fact. Every lifecycle or owner-observation failure writes one
closed continuity fact with elapsed duration and a closed reason instead of
silently omitting evidence.

Every process attempt uses one short, mode-0700 HOME below the invoking user's
`~/.dhq5` root. A single owner retains the exact App PID, Herdr socket, Agent
PID ledger, and private tmux namespace until all are quiescent, then removes
that HOME. Cleanup failure blocks the result; the harness never suppresses a
temporary-directory cleanup error and never places this diagnostics-bearing
HOME below `/private/tmp`.

The same owner seam covers every provider subprocess reachable from
`--scale-endurance`: the raw 16-Agent Herdr preflight, each cold Shell timing
attempt, and `scripts/check-agent-runtime-real.sh`. The shell harness receives
an explicit `DEVHUB_Q5_SECURE_RUN_ROOT` from the driver and creates one
mode-0700 child below it; when invoked directly, it uses a mode-0700 child of
`~/.dhq5`. HOME, provider configuration, sockets, tmux namespaces, and PID
ledgers never fall back to `TMPDIR`, `/tmp`, or `/private/tmp`. Exact cleanup is
part of acceptance rather than a best-effort test teardown.

Screen and input checks are a final user-attended phase only. They run after
the MVP implementation, all noninteractive checks, all implementation commits,
and the final completion audit. The explicit manual entry point is:

```sh
python3 scripts/q5-native.py --execute --interactive-manual \
  --accept-official-vscode-license
```

Automation must not invoke `--interactive-manual`. Reports keep
`interactive-native-input` at `status: deferred` with reason
`user_interaction_environment_deferred`; deferred never means passed or
blocked.

The consent flag is per-run and is the only path by which the driver sets
`DEVHUB_VSCODE_SERVER_LICENSE_ACCEPTED=1`. DevHub never downloads, copies, or
silently accepts the official VS Code license. A bounded legacy smoke may be
run separately with `--legacy-openvscode-smoke`; it cannot provide primary
Q5.2 evidence.

The driver checks the execution boundary before launching a GUI process. When
`CODEX_SANDBOX` is present, it records
`native_execution_boundary_unavailable`, skips native launches, and never
labels the resulting slots as marker timeouts. The command does not escalate
itself; run it from an approved native GUI boundary.

The driver launches the built DevHub process with an isolated temporary HOME
and a private 0700 tmux socket directory, gracefully quits each owned process,
and reaps only resources belonging to the exact run. The process-only path does
not query or manipulate native controls. It opts into
Rust-owned readiness markers, performs one untimed setup launch and ten
measured launches, and preserves only closed marker observations and elapsed
milliseconds. Terminal attach probes record only command entry, an exhaustive
typed error marker, invoke rejection, or success; they never record paths,
identifiers, argv, stderr, or terminal content. It also runs the real Herdr
and tmux checks; provider output, executable locations, and user paths are
discarded. Bounded app/provider PIDs and Bridge generations are retained only
as evidence identity facts. A missing marker, official CLI, or GUI session creates a
bounded blocked attempt, never a synthetic timing sample. The driver does not
promote manual WebView input or reference hardware evidence: those entries
remain explicitly `deferred` with
`user_interaction_environment_deferred` until the final user-attended phase.

To record native evidence, create a short-lived redacted input containing only
the raw elapsed milliseconds (one setup run is implicit in the record format):

```json
{
  "timings": {
    "mounted_activity_switch": {
      "samples_ms": [12.1, 11.9, 12.4, 12.2, 12.0, 12.6, 12.3, 12.1, 12.5, 12.2],
      "measurement_kind": "native-manual",
      "reason": "Reference Mac run; input-to-visible Activity response."
    }
  }
}
```

Then merge and validate it:

```sh
python3 scripts/q5-performance.py --record \
  --input /path/to/redacted-q5.2-input.json \
  --output docs/evidence/q5.2-reference-report.json
python3 scripts/q5-performance.py --check \
  --report docs/evidence/q5.2-reference-report.json
```

The report preserves all ten raw samples and computes nearest-rank p95. A
timing is `pass` only when all ten samples exist and p95 is within its budget;
missing or partial data remains `pending`. Reports must omit serial numbers,
hardware UUIDs, user names, host names, absolute paths, and unbounded process
output. The harness records only OS/tool versions, architecture, and bounded
redacted evidence.

## Timing budgets

Every scenario uses one untimed setup followed by ten measured runs. The
definitions are the ones in [`ACCEPTANCE-METHOD.md`](ACCEPTANCE-METHOD.md),
and the budget applies to p95 on the reference context.

| Scenario | p95 budget |
| --- | ---: |
| Process-cold Shell presentation | 2 s |
| Scratch interactive response | 3 s |
| Workspace Picker first result, with responsive query input during scan | 300 ms |
| Mounted Activity switch | 100 ms |
| Cold OpenVSCode interactive response | 10 s |
| Warm Workbench reconstruction | 5 s |

Interactive means that the target Surface accepts input and produces its local
response. Native chrome, an open port, a TCP connection, or a WebView creation
event alone is not an interactive sample.

## Scale and endurance matrix

The reference-Mac run must keep stable identities while exercising:

- 8 open Workspaces and 16 live Agents distributed across at least 4
  Workspaces.
- 9 Editor WebViews: Global plus 8 Workspace Editors.
- At least 5 hidden Editor Surfaces for 10 minutes, then load identity, Bridge
  connection, and dirty-state continuity.
- Full process-targeted Quit/relaunch 5 times while at least 2 Agents and 2 Workspace tmux
  sessions remain active. Every cycle separately verifies the editor port is
  available after Quit, no editor process remains, navigation is the expected
  Workspace Editor, persisted state is exactly 8 Workspaces/16 Agents/16
  provider mappings, and all 9 exact Bridge identities are connected, ready,
  and carry nonzero generations. Port release is a bounded quiescence barrier:
  the provider-specific stable port must bind twice consecutively within two
  seconds, with zero remaining listeners. The report retains only its closed
  provider-file class, listener count, ownership boolean, and release category.

The report records each requirement separately. A scale `pass` is invalid
unless the exact counts, continuity checks, and owned cleanup result are
present. Native post-return input and 10 Window close/reconstruction cycles are
separate deferred user-attended items and do not block the process-only gate.

## Independent crash and tmux checks

Crash only one provider at a time: the managed OpenVSCode child, the Herdr
connection/server path, and one owned tmux session. For each case, verify the
other Surfaces remain live, the failed provider reports degraded state, and the
failed provider recovers without identity loss. The report cannot mark a crash
case `pass` without both isolation and recovery evidence.

The existing real-tmux transition matrix remains authoritative. Its required
cases are absent target, wrong-marker conflict, marked-target conflict,
preserved unknown sessions, partial old cleanup, crash/relaunch at each
persisted transition state, and recreation failure after the new effective
socket name commits. No unmarked session may be mutated, and the old socket
name must never be reported effective after the new-name commit.

The local provider commands are:

```sh
# Existing deterministic and real tmux/provider suites
cargo test --offline --locked -p devhub-app --lib terminal:: -- --nocapture
scripts/check-agent-runtime-real.sh

# Full implementation checks required before status promotion
CI=true pnpm run check
CI=true pnpm run build
CI=true pnpm --filter @devhub/app exec tauri build --debug --no-bundle
git diff --check
```

When an external binary, separately installed official CLI, display server, or
execution boundary is unavailable, noninteractive timing/provider evidence
records `pending` or `skipped` with the exact reason. Screen/input and Window
reconstruction evidence instead remains the explicit `deferred` item described
above. Local unit/provider tests and the report contract are not substitutes
for the reference-Mac timing and ten-minute WebView continuity gate.
